# twoWatch · Cinema Together

Windows-приложение для совместного просмотра локальных видео. Организатор
запускает WPF-приложение, выбирает фильм и отправляет ссылку друзьям. Друзьям
нужен только браузер. Видео передаётся с компьютера организатора; облачное
хранилище, подписка и выделенный сервер не нужны.

## Быстрый запуск

1. Распакуйте **весь** архив `CinemaTogether-win-x64.zip` в обычную папку.
2. Запустите `CinemaTogether.exe` на Windows 10/11 x64. .NET устанавливать не нужно.
3. В «Настройках» задайте имя и пароль комнаты, оставьте IP `0.0.0.0` и порт `8080`.
4. В «Медиатеке» добавьте файлы или папку с видео.
5. На главной запустите сервер, выберите фильм в медиатеке и нажмите «Смотреть выбранное».
6. Скопируйте ссылку с IP нужного сетевого интерфейса. Передайте другу ссылку и пароль.
7. Друг вводит имя и пароль в браузере. Когда все загрузили видео, организатор нажимает ▶.

Для встроенного плеера нужен [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/).
На современных Windows с Edge он обычно уже установлен. При его отсутствии
приложение покажет сообщение. Организатор может открыть локальный плеер в desktop,
а зрители используют Chrome, Edge, Firefox или Safari с поддержкой выбранного кодека.

Архив со сборкой доступен в **Actions → Build and test → успешный запуск → Artifacts → CinemaTogether-win-x64**.
Сборка включает FFmpeg/FFprobe, если выполнен скрипт с `-IncludeFFmpeg`. В сборке без
них установите обе программы самостоятельно и укажите пути в настройках.

## Что реализовано

| Возможность | Реализация |
|---|---|
| Desktop | WPF, асинхронный запуск/остановка Kestrel, настройки JSON, WebView2 |
| Медиатека | SQLite, файлы и рекурсивный импорт папок, анализ FFprobe |
| Форматы | MP4, WebM, MKV, AVI, MOV, M4V; прямое воспроизведение или FFmpeg |
| Передача | Авторизованные HTTP Range-запросы, оригинальное качество без перекодирования |
| Синхронизация | SignalR, серверные часы, play/pause/seek/rate/смена видео |
| Буферизация | Общая пауза, автоматическое продолжение после готовности всех |
| Переподключение | Актуальные фильм, позиция, права и последние сообщения |
| Доступ | Пароль PBKDF2, HttpOnly-сессии, отзыв сессии при отключении, проверка прав на сервере |
| Общение | Чат, список участников, выдача/отзыв управления, голос WebRTC |
| Плеер | Громкость, полный экран, качество, выбор звука и текстовых субтитров |
| Просмотр | Очередь и история последних 100 выборов фильма |
| Диагностика | Состояние сервера, ссылки интерфейсов, счётчик/скорость передачи, проверка инструментов и локального порта, журналы |
| HTTPS | Пользовательский PFX-сертификат на Kestrel |

Следующий фильм из очереди запускает организатор кнопкой «Следующее видео».
Кнопка ▶ не запускает просмотр автоматически при выборе фильма.
Громкость, субтитры, полноэкранный режим, качество и звуковая дорожка индивидуальны.

## Подключение по сети

### Одна локальная сеть

Оставьте `0.0.0.0:8080`, запустите сервер и используйте ссылку вида
`http://192.168.1.20:8080`. `localhost` и `127.0.0.1` работают только на компьютере
организатора. В списке ссылок на главной можно выделить и скопировать нужный адрес.

При необходимости разрешите входящие TCP-подключения к выбранному порту в Windows
Firewall. Само приложение работает без администратора и не изменяет firewall.
Для изменения системного сетевого правила Windows может запросить права администратора.

### Интернет без настройки роутера

Установите Tailscale или ZeroTier на компьютеры участников и подключите их к одной
приватной сети. Используйте IP организатора в этой сети. При HTTP VPN защищает
транспорт между участниками; без VPN обычный HTTP не шифрует пароль, чат и видео.
Само приложение не зависит от этих продуктов и не обращается к ним через API.

### Публичный IP

Нужен доступный извне IP и перенаправление **TCP** выбранного порта на LAN-IP
компьютера организатора. Ссылку составьте с публичным IP вместо LAN-IP; приложение
показывает локальные адреса интерфейсов, а не определяет публичный IP.
При CGNAT у провайдера входящие подключения обычно недоступны — используйте VPN
или запросите публичный IP у провайдера. Доступность извне проверяйте с другого
подключения, например через мобильную сеть. Диагностика локального порта не
доказывает доступность через интернет. Автоматического UPnP-проброса портов нет.

### HTTPS

В настройках укажите путь к PFX и его пароль. Сертификат должен быть доверенным
на клиентских устройствах и соответствовать используемому имени/IP. Для встроенного
плеера включите в сертификат `127.0.0.1`: desktop подключается через loopback.
Приложение не отключает проверку сертификатов. Пароль PFX не записывается в JSON;
его нужно вводить перед запуском или задавать `CINEMA_CERT_PASSWORD` для headless-сервера.
Изменения настроек и пароля комнаты выполняются при остановленном сервере.

### Голосовой чат

Нажмите «Голосовой чат» и разрешите микрофон. Есть отдельная кнопка выключения микрофона.
Браузер разрешает микрофон только через **HTTPS** или с `localhost`/`127.0.0.1`.
Голос идёт напрямую между браузерами по WebRTC, сигнализация — через авторизованный
SignalR. Для связи нужны доступные друг другу LAN/VPN-адреса. Публичные STUN/TURN
сервисы не используются; голос между произвольными NAT без VPN не гарантируется.
При потере связи микрофон выключается, повторное подключение к голосу выполняется кнопкой.

## Видео и перекодирование

FFprobe читает кодеки, длительность, разрешение и дорожки во время импорта.
MP4/MOV/M4V с H.264 + AAC/MP3 и WebM с совместимыми кодеками передаются напрямую.
Возможности декодирования зависят от браузера и устройства. Если оригинал не
проигрывается, выберите, например, 720p: будет подготовлен H.264/AAC MP4.

Для MKV/AVI и несовместимых кодеков создаётся локальная копия MP4. При качестве
«Оригинал» совместимый H.264 копируется без повторного кодирования; звук переводится
в AAC. Качество 1080p/720p/480p задаёт максимальную высоту без увеличения исходного
разрешения. Выбор другой звуковой дорожки создаёт отдельную копию.

Подготовка заканчивается **до** начала воспроизведения копии, чтобы Range и перемотка
работали по законченному файлу. На длинных фильмах подготовка может занять много
времени. Это не потоковый HLS-транскодер. Одновременно работает один FFmpeg, очередь
ограничена четырьмя задачами, готовые копии переиспользуются. Перед новым заданием
старые копии удаляются, если кэш превышает 20 ГиБ; это мягкий лимит, один файл может
увеличить его. Кэш можно очистить вручную при остановленном приложении.

Кодировщик по умолчанию — `libx264`. В настройках доступны `h264_nvenc` (NVIDIA),
`h264_qsv` (Intel) и `h264_amf` (AMD). Используется соответствующий GPU-кодировщик,
если он запускается; при ошибке выполняется повтор на CPU. Декодирование остаётся
программным. Реальная поддержка зависит от оборудования, драйвера и сборки FFmpeg.

Текстовые встроенные субтитры преобразуются в WebVTT. Графические PGS/DVD-субтитры
и прожиг субтитров не реализованы. При смене фильма локальные дорожки и качество
сбрасываются. История хранится в SQLite, очередь и чат — в памяти до остановки сервера.

## Сборка из исходников

Нужны .NET SDK **10.0**, Node.js **22+** для изменения SCSS/JS-зависимостей,
FFmpeg/FFprobe для импорта и медиатестов. WPF можно скомпилировать на Linux с
`EnableWindowsTargeting`, но запускать desktop нужно на Windows.

```powershell
git clone https://github.com/KUPRYAKOFF/twoWatch.git
cd twoWatch
npm ci
npm run build
dotnet build CinemaTogether.slnx
dotnet test tests/CinemaTogether.Tests
dotnet run --project src/CinemaTogether.Desktop
```

Скомпилированные CSS и локальный SignalR-клиент включены в репозиторий: для одной
только .NET-сборки Node.js не нужен. После изменения SCSS или npm-зависимостей
выполните `npm run build` и закоммитьте обновлённые браузерные файлы.

Автономная portable-сборка для Windows x64:

```powershell
./scripts/publish.ps1 -IncludeFFmpeg
# artifacts/CinemaTogether-win-x64.zip
```

Скрипт фиксирует архив FFmpeg и проверяет SHA-256. Без флага `-IncludeFFmpeg`
инструменты должны быть установлены отдельно. Автообновлений и установки службы нет.
Не переносите один `exe` отдельно от папок, DLL и `wwwroot`.

### Запуск сервера отдельно для разработки

```powershell
$env:CINEMA_PASSWORD = "change-this-password"
$env:CINEMA_DATA_DIR = "$PWD/data"
$env:CINEMA_PORT = "8080"
$env:CINEMA_IMPORT = "C:\Videos\movie.mp4" # файл или папка, необязательно
dotnet run --project src/CinemaTogether.Server
```

`CINEMA_PASSWORD` при наличии обновляет сохранённый хеш пароля; затем переменную можно
удалить. `CINEMA_HOST_SECRET` — отдельный случайный секрет не короче 32 символов для
локальной developer-сессии организатора. Откройте
`http://127.0.0.1:8080/#host=<секрет>`. Секрет немедленно удаляется из адресной строки,
принимается только через loopback и не нужен зрителям. В desktop создаётся случайно
при каждом запуске сервера. Не публикуйте его в ссылке приглашения.

### Проверки

```powershell
dotnet test tests/CinemaTogether.Tests
dotnet build src/CinemaTogether.Server
npx playwright install chromium
npm run test:e2e
./scripts/windows-smoke.ps1 # после publish, только Windows
```

Тесты проверяют серверные часы, буферизацию и отключение блокирующего участника,
права, сессии, лимит входов, Origin, HTTP Range, SQLite, реальное преобразование
видео и извлечение субтитров. Браузерный сценарий проверяет двух участников,
play/pause/seek, рассинхронизацию, чат, WebRTC с тестовым микрофоном, права,
переподключение, отзыв доступа и мобильную ширину. Изображения проверки сохраняются
в `artifacts/e2e`. `CHROMIUM_PATH` позволяет выбрать установленный Chromium,
`DOTNET_COMMAND` — путь к dotnet. CI собирает и проверяет сервер на Linux, затем
создаёт portable-архив и проверяет открытие WPF-окна на Windows.

Если корпоративная политика браузера запрещает прямой WebRTC/UDP, можно отдельно
запустить остальные E2E-проверки с `CINEMA_SKIP_VOICE_MEDIA=1`. Сценарий явно пишет
`SKIP`, а серверная проверка авторизации голосовой сигнализации остаётся в .NET-тестах.

## Архитектура и хранение

```text
src/CinemaTogether.Core           модели и атомарные переходы состояния комнаты
src/CinemaTogether.Infrastructure SQLite, JSON, PBKDF2, FFprobe и очередь FFmpeg
src/CinemaTogether.Server         Kestrel, сессии, HTTP Range, SignalR, WebRTC-сигнализация
src/CinemaTogether.Server/wwwroot HTML, JS, готовый CSS, локальный SignalR
src/CinemaTogether.Server/Styles  исходный SCSS
src/CinemaTogether.Desktop        WPF, WebView2 и управление жизненным циклом сервера
tests/CinemaTogether.Tests        модульные, HTTP/SignalR и медиатесты
```

Единственный источник времени — сервер. Он сохраняет позицию при каждом переходе
и вычисляет текущую позицию из времени и скорости. Клиент оценивает смещение часов
по Ping. Ошибка до 100 мс игнорируется, 100–500 мс исправляется временной скоростью
до ±5%, более 500 мс — перемоткой. Подключение нового зрителя к текущему фильму
также приостанавливает комнату до его готовности. При выключении сервера все
подключения закрываются, задания FFmpeg отменяются.

По умолчанию данные в `%LOCALAPPDATA%\CinemaTogether`:

- `settings.json` — параметры и солёный PBKDF2-хеш пароля, без пароля PFX;
- `library.db` — медиатека и история;
- `cache` — подготовленные MP4;
- `logs` — ошибки desktop и серверные предупреждения/ошибки, серверные журналы за 14 дней;
- `webview` — профиль встроенного браузера.

Открытые сессии живут до 24 часов, отзыва или остановки сервера. Секрет сессии
отделён от публичного ID участника. Cookie имеет HttpOnly/SameSite=Strict и Secure
при HTTPS. Файлы доступны только по ID медиатеки, абсолютные пути не выдаются
веб-клиенту. Символические ссылки при импорте/передаче запрещены. FFmpeg запускается
без shell, с отдельными аргументами, без возможности передать произвольную команду
через веб-клиент. Чат отображается как текст. По умолчанию до 12 участников;
фактический предел определяется исходящей скоростью и производительностью хоста.

Автоматическое изменение firewall/UPnP, NAT traversal с TURN и установщик с цифровой
подписью не входят в эту версию. См. [уведомления о сторонних компонентах](THIRD-PARTY-NOTICES.md).
